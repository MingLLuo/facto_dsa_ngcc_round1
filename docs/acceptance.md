# Acceptance: forging signatures for the authors' own verifier

## What is checked

1. A public key is taken from the vendored KAT file (or generated by the model
   for a synthetic instance) and encoded exactly as the authors' code expects,
   `m * C(2n+2,3)` little-endian `uint16` values.
2. A helper compiled from the vendored sources computes the protocol target
   `h = xof_field(sm3(pk), message)` using the reference `sm3_digest` and
   `xof_field` themselves.
3. The attack produces `z` with `P(z) = h`, which is encoded as `2n`
   little-endian `uint16` values (40 bytes for the 128-bit set).
4. The authors' `sig_verify(pk, sigma, message)` is called on the result, and on
   a copy with one bit flipped as a negative control.

## Recorded result

`results/acceptance/acceptance.json`:

```
source:                    kat (vendored 128-bit KAT, first PK)
public_key_bytes:          40040
signature_bytes:           40
sig_verify_return_code:    0        <- accepted
negative_control_flipped:  -1       <- rejected
acceptance:                ACCEPTED by the authors' sig_verify
```

The same check also passes for a synthetic 128-bit key generated by the model.

## Independent re-check in SageMath

`scripts/verify_with_sage.py` (`make sage-check`, i.e.
`sage -python scripts/verify_with_sage.py`) repeats the three claims of the
finding with a different toolchain and no shared code:

```
[ok  ] forged signature satisfies P(z) = h     polynomial substitution in GF(65519)
[ok  ] derivative rank                          165 of 210
[ok  ] missing dimensions                       45 = n(n-1)/2
[ok  ] annihilator image dimension              10 = n
[ok  ] every public cubic vanishes on W         P|_W = 0
```

Sage is used only for this re-check.  The solving stage stays with `msolve`,
because `ideal.variety()` has to build a lex Groebner basis and ran for more
than ten minutes on the reduced system that `msolve` answers in under a second;
the linear algebra is FLINT in both cases.

## Reproduce

```sh
python3 scripts/run_acceptance.py --source kat     # vendored KAT public key
python3 scripts/run_acceptance.py --source model   # synthetic 128-bit key
```

## Not covered

256- and 512-bit acceptance: the vendored materials ship 256-bit KAT keys but no
512-bit ones, and the solve stage is out of reach at those sizes for the reason
explained in `docs/complexity.md`.
